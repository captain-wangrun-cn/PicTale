# 显影 DEVELOP

把一组图片里的细节，显影成一个故事。

上传或拖入多张图片，AI 先逐帧识别画面中的人物、动作、场景、物品和文字；你决定每一条细节是**展开**、**提及**还是**略过**，再选择创作力度、视角、全篇篇幅、风格及自定义 Prompt，把顺序排列的图片写成**同一个连续故事**。故事里的每一段都能结合全篇上下文单独重写。

## 快速开始

```bash
node server.mjs
```

然后打开 <http://127.0.0.1:5173>（需要 Node 18+，无第三方依赖）。

页面上的请求会经过本机的 `server.mjs` 转发到 AI 服务，所以不受浏览器跨域限制，API Key 也不会发给除你配置的服务之外的任何地方。

想先看看效果：点左下角「载入示例」，或直接打开 <http://127.0.0.1:5173/?sample>。

## 连接 AI

点右上角「设置」，填入：

| 项目 | 说明 |
| --- | --- |
| 接口地址 | OpenAI 兼容接口，填到 `/v1` 为止。例如 `https://api.openai.com/v1` |
| API Key | 只保存在本机浏览器的 localStorage |
| 写作模型 | 生成故事用，任意对话模型 |
| 视觉模型 | 识别图片用，**必须支持图片输入**；留空则使用写作模型 |

常见服务的地址示例（模型名以各家文档为准）：

| 服务 | 接口地址 | 视觉模型示例 |
| --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o` |
| OpenRouter | `https://openrouter.ai/api/v1` | `openai/gpt-4o` |
| 月之暗面 | `https://api.moonshot.cn/v1` | `moonshot-v1-8k-vision-preview` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4v-plus` |
| 阿里通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-vl-max` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-VL-72B-Instruct` |
| DeepSeek | `https://api.deepseek.com` | 暂不支持图片，可用作写作模型 |

填完可以点「测试连接」验证。

## 使用流程

1. **放入图片** — 拖入或点击选择，多张图片按顺序排列；可拖动排序，或用帧上的 ↑ ↓ 调整顺序。每张图可以补一句说明（人物是谁、时间、你想强调什么）。
2. **识别细节** — 「识别这一帧」或「识别全部」。识别结果是一份可编辑的清单：人物 / 动作 / 场景 / 物品 / 文字 / 跨图线索。点任意一条，图上会框出它的位置。
3. **挑选重点** — 每条细节有 略 / 提 / 展 三档：展开的会被具体描写，提及的自然带过，略过的不单独写。上方的条显示这一帧的注意力分配。识别错了可以改，漏了可以手动补充。
4. **生成故事** — 选择 忠实 / 润色 / 自由，设定视角、全篇篇幅与 自然 / 直白 / 艺术 / 委婉 风格。所有图片按顺序展开**同一个连续故事**，人物、物品状态和情节前后承接，而不是逐图说明。段落旁的 F 编号只是编辑定位标记，鼠标移到编号旁可以重写对应片段；复制与导出 Markdown 会去掉这些内部标记。
5. **自定义 Prompt** — 展开生成按钮上方的「自定义 Prompt」，选择「默认创作」或「自然表达」预设，再直接编辑附加创作要求。编辑框的内容用于全文生成和段落重写，不参与图片识别；留空恢复默认要求。风格与 Prompt 随当前项目自动保存，切换项目分别恢复。预设只调整写作要求，不保证改变模型自身能力或限制。

调整图片顺序或增删图片后，原稿不会被清除；页面会提示图片与故事定位已不一致。请重新生成全文后再使用按图重写，避免把新顺序的画面依据套进旧段落。

快捷键：`Ctrl/⌘ + Enter` 生成或停止生成，`Ctrl/⌘ + S` 保存项目。

## 项目与保存

内容会自动存进当前项目，打开页面时恢复最近用的那个。顶栏显示项目名，点它打开项目列表：

- **自动保存** — 改动在 0.4 秒后写入当前项目，离开页面时也会补一次。
- **命名保存** — 第一次保存会问项目名（`Ctrl/⌘ + S` 同效）；已命名后按保存直接写入。
- **项目列表** — 打开、重命名、删除任意项目，或「另存为副本」保留当前版本再改。
- **新建项目** — 清空工作区另起一个，原来的项目仍在列表里。
- **删除当前项目** — 桌面上的内容会保留，之后的改动会存成一个新项目。

旧版本只有一份自动存档，第一次打开新版本时会自动迁移成第一个项目。

## 数据与隐私

- 项目存在浏览器的 IndexedDB 里，按项目分开保存，刷新或关掉页面不会丢；「清空项目」只清空当前项目的内容。
- API Key 存在 localStorage，只在你配置的接口地址上使用，**不会上传云端**（见下）。
- `server.mjs` 默认监听 `0.0.0.0`，局域网内其他设备也能访问；不需要时用 `HOST=127.0.0.1 node server.mjs` 只监听本机。

## 账号云端同步

登录 wris.me 账号（右上角，GitHub 授权）后，项目会和账号云端双向同步：

- 帧图按内容哈希上传到 Cloudflare R2，项目数据（不含图片本体）存 D1，由一个 Cloudflare Worker 提供 API，部署步骤见 [`worker/README.md`](worker/README.md)。
- 打开页面时做一次双向合并：`updatedAt` 新者胜；删除用墓碑在多台设备间收敛。编辑过程中改动会防抖推送到云端。
- 未登录时一切照旧，只保存在本机浏览器。
- **AI 接口配置（接口地址 / API Key）不参与云端同步**，每台设备各自填写。


## 常见问题

**提示「本地服务未运行」** — 用 `node server.mjs` 启动，并通过 `http://127.0.0.1:5173` 打开，不要直接双击 `index.html`。

**识别失败（400 / 422）** — 多半是模型不支持图片输入，换一个视觉模型；也可能是模型名写错。

**找不到接口（404）** — 接口地址通常需要以 `/v1` 结尾，程序会自动补上 `/chat/completions`。

**字体** — 故事使用「霞鹜文楷」，从 jsDelivr 加载；加载不到时回退到本机的楷体。
